# Before / after

말투 기준 샘플. 내용은 예시일 뿐이고, 리듬·단어 선택을 본다.

## 1) 답변 설명

**Before**

핵심은 이거예요. 캐시를 도입했다. 응답이 빨라진다. 리스크는 무효화 경로다.
정리하면 다음과 같습니다. 캐시 레이어를 심고 TT를 세워 일관성을 살린다.

**After**

캐시를 넣어서 응답을 줄이려는 거고, 조심할 건 무효화 경로예요.
TTL이랑 키 규칙만 맞춰 두면 일관성은 대체로 유지돼요.

## 2) PR 설명

**Before**

### 무엇을 왜
본 변경은 설치 스크립트에 검증을 박아 실패를 조기에 드러낸다.
부수 이득으로 DX가 열린다.

**After**

설치 스크립트에 검증을 넣었어요. 깨진 의존성이 나중에 터지지 않게요.
쓰는 쪽에서는 실패가 더 빨리 보여서 고치기 쉬워집니다.

## 3) 커밋 메시지 (해라체)

**Before**

feat: 사용자 여정에 가드레일을 심어 DX를 끌어올린다

**After**

feat: 설치 검증을 추가해 의존성 실패를 일찍 잡는다

## 4) 리뷰 코멘트

**Before**

이 추상화는 필수다. 결합도를 낮춘다. 다만 네이밍이 직관을 저해한다.

**After**

추상화 자체는 괜찮은데, 이름만 보면 역할이 잘 안 읽혀요.
`loadManifest` 쪽이 의도에 더 가까울 것 같아요.
